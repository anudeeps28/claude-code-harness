# Scripts

Maintainer tooling for this repository: the dogfood links and the boundary checks that `npm test` runs.

## Interface

**Inputs:** `node scripts/dogfood.js` (`npm run dogfood`) takes no arguments; it reads `.claude/.harness-manifest.json` to find the selected tracker and code-platform adapters. Every `check*` in `lib/boundaries.js` takes the repo root and an optional options object whose only key is `exempt` (the skill folders whose Interface block is not required); any other key is refused by name. They read `skills/`, `agents/`, `rules/`, `CONTEXT.md`, the code modules' `README.md` files, and every `.js` file outside `__tests__/`, `tasks/`, `.claude/`, `_local/` and `node_modules/`.

**Outputs:** `dogfood.js` turns the `.claude/` entries for skills, agents, hooks, rules and the selected adapters into symlinks to the repo source and prints what it linked. Every check returns a list of problem strings, each naming the file or module at fault; an empty list means the boundary holds. The `scripts/__tests__/boundaries-*.test.js` files fail `npm test` on any problem.

**Callable parts:** `dogfood.js`, and `dogfood-links.js` with its two exports `planLinks` (the link plan) and `STATIC_DIRS` (the four dirs linked wholesale: skills, agents, hooks, rules). The checks in `lib/boundaries.js`: `checkOwners`, `checkRulesTable`, `checkInterfaces`, `checkCallableParts`, `checkFilePointers`, `checkHeadingPointers`, `checkAgentOutputs`, `checkSharedInputs`, `checkSkillUsage`, `checkReadmes`, `checkReadmeCallable`, `checkAdrModules`, `checkAdrCitations`, `checkAcceptedAdrsCited` and `checkContextMap`, plus the helpers and data `agentOwners`, `listModules`, `readModule`, `PART_LABELS` (the four Interface part labels and their keys), `readInterface`, `callersOf`, `namedFiles`, `buildPointerIndex`, `requiredExports`, `readArchitectureMap`, `moduleIds` and `CODE_MODULES` (the five code modules). That is every export of `lib/boundaries.js`. `lib/common.js` (shared helpers: the option guard, folder listings, code-fence tracking) and the other files in `lib/` are private. `checkReadmeCallable` is check 1: a relative require, `require.resolve` or `import()` into another module must name a file that module's Interface lists — a code module's `README.md` Callable parts, or for `skills/<name>/` that skill's `SKILL.md` Callable parts. It also reports a require whose argument is not a string literal, as `<file>:<line>: cannot check a non-literal require`. `checkCallableParts` and `checkFilePointers` are check 2: a skill, agent or rule names another module's file only when it is that module's main file (`SKILL.md`, the agent's `.md`, `README.md`) or a file its Interface lists; `trackers/active/<x>` and `code-platform/active/<x>` are read as the adapter script `<x>`, and a leading `.claude/` is ignored. `checkHeadingPointers` reports a path followed by a quoted or bold heading other than `Interface`, when the path is a module's main file. Only `install`'s own tests require a file from here (`dogfood-links.js`); a test is not a requirer under the boundary rule, so no other module requires anything from `scripts`.

**Never breaks:** Pure Node.js stdlib, no runtime dependencies. A check only reads the repo and never edits it. `dogfood.js` converts only the dirs it names and needs a base install first.
